# Pi → Windows 地面站：上报 API v1

本文是车端开发的线协议参考，记录当前框架实际识别的全部消息。网络配置、ROS 坐标变换和可选联调步骤另见 [Pi 端联调手册](./Pi端联调手册.md)。

## 连接与消息总表

Pi 是 WebSocket 服务端，Windows 地面站是客户端。地面站连接 `ws://<Pi地址>:<端口>/ws` 或 `wss://…/ws`；8765 是示例端口。路径固定为 `/ws`，不带账号、密码、查询串或片段。握手成功后 Pi 主动推送，不等订阅。上位机握手等待最多 8 秒。不发送业务 ACK、控制指令或应用层心跳；连接关闭后由操作者重连。建议只在受信任的联调网络开放。

| type | Pi 上报内容 | 上位机用途 |
|---|---|---|
| `task_state` | 完整任务快照 | 任务状态、阶段、进度、说明 |
| `event` | 一次性事件 | 操作台日志 |
| `telemetry` | 单通道的一个实测标量 | 遥测数值与历史曲线 |
| `scan_lite` | 一次 map 坐标系的二维扫描 | 地图点云 |

每条 WebSocket 文本消息恰好一个 UTF-8 JSON 对象。不要发送 JSON 数组、二进制帧或把多条 JSON 拼进同一条消息。上位机单条文本上限为 262144 个 UTF-16 码元。所有消息必填 `schema_version:1`（数字）、`type`（表内字符串）及 `ts_ms`（非负安全整数，最大 9007199254740991，Unix 毫秒）。采集类使用采样时刻，事件用发生时刻，快照用生成时刻。坏 JSON、未支持的类型／版本、字段校验失败会记录协议错误并断开；不要依赖额外字段触发任何行为。

## task_state：任务快照

| 字段 | 类型与约束 |
|---|---|
| `seq` | 非负安全整数；同一连接严格递增，换任务也不归零，重连可重置 |
| `run_id` | 本次任务运行 ID；待命时为 `null`，每次新运行用新 ID |
| `state` | `idle` 待命、`running` 执行中、`paused` 已暂停、`estop` 急停锁定、`succeeded` 已完成、`failed` 失败、`cancelled` 已取消 |
| `progress_pct` | 整数百分比，不是 0–1 小数 |
| `stage_id` | 当前或最后一个阶段的 ID；待命或完成时填 `null` |
| `stages` | 按显示顺序排列的 `{id,label}` 对象数组；非待命 1–32 项，ID 不重复，标签非空白且最长 80 个 UTF-16 码元 |
| `detail` | 唯一可选字段；有值时是非空白字符串，最长 256 个 UTF-16 码元，不填可省略 |

各 ID 须匹配 `^[a-zA-Z0-9][a-zA-Z0-9_.:-]{0,63}$`。待命要求 `run_id:null, stage_id:null, progress_pct:0, stages:[]`。完成要求有效 `run_id` 和阶段列表、`stage_id:null, progress_pct:100`。其余状态进度为 0–99，且 `stage_id` 必须出现在列表里。由 Pi 决定状态迁移和进度，上位机只显示，不自行推进。

每帧只包含一个任务的完整快照。多任务共享同一连接，按各自 `run_id` 交错发送，例如 `seq=42` 发 `run-01`、`seq=43` 发 `run-02`、`seq=44` 再发 `run-01`。`seq` 全连接共用，不按任务分开计数。连接后发送各任务的完整快照，变化时立即推，无变化建议各自每秒续发。重复及倒序帧忽略；每个任务按自己的接收时间计时，3.5 秒无新帧单独标为过期。

新版前端在「任务 → 显示任务」按 `run_id` 勾选，可同时显示多个。取消勾选只隐藏卡片，仍接收和更新快照；重新勾选显示最新状态。当前会话最多保留 32 个任务，超出时优先淘汰过期或已结束的任务，再按最早更新顺序淘汰。`idle` 只在没有已知任务时显示，不清空其他任务；结束某次运行需上报其终态。断开清空任务及勾选状态。

~~~json
{"schema_version":1,"type":"task_state","ts_ms":1795000000100,"seq":42,"run_id":"run-01","state":"running","progress_pct":35,"stage_id":"pickup","stages":[{"id":"pickup","label":"取料"},{"id":"deliver","label":"放料"}],"detail":"已到达原料区"}
~~~

## event：事件

必填 `level`（`info`、`warn` 或 `error`）、`source` 和 `message`（非空白字符串）。日志来源添加 `Pi / ` 前缀，界面日志来源和正文截取至 96 和 4096 个 UTF-16 码元；正常范围内按车端 `ts_ms` 记录时间。事件不会更新任务状态或进度；如两者都要更新，分别发事件与快照。当前没有事件 ID 去重或重连补发协议。

~~~json
{"schema_version":1,"type":"event","ts_ms":1795000000110,"level":"info","source":"mission","message":"已到达原料区"}
~~~

## telemetry：实测遥测

必填 `channel`、`unit`（精确匹配下表）及 `value`（有限 JSON 数字）。每消息只发一个通道；不要用指令值或替代零冒充实测值。

| channel | unit | 含义 |
|---|---|---|
| `gyro` | `°/s` | 机体 Z 轴角速度，俯视逆时针为正 |
| `motor` | `rpm` | 约定驱动电机的反馈转速，前进为正 |
| `fused_x` | `m` | map 坐标的融合 X 位置 |
| `fused_y` | `m` | map 坐标的融合 Y 位置 |
| `fused` | `°` | 融合航向，map +X 为零，逆时针为正 |

每通道时间戳应严格递增；在新鲜度校验通过后，重复或倒序样本忽略。与上位机时钟差的绝对值超过 1500 ms 的采样是协议错误。已接收样本停更后，当前值显示无数据，不补零；重连清空旧会话历史。融合位置通道供遥测使用，不驱动模拟车图标。

~~~json
{"schema_version":1,"type":"telemetry","ts_ms":1795000000120,"channel":"gyro","unit":"°/s","value":-2.5}
~~~

## scan_lite：轻量二维点云

必填 `frame_id:"map"` 和 `points`（最多 4096 个 `[x,y]` 点，每点恰好两个有限数字，单位米）。场地地图原点在左下，+X 向右、+Y 向上；由 Pi 用采样时刻的 TF 转至 map，不做屏幕 Y 翻转。空数组代表有扫描但无有效回波，不代表断流。接收时与上位机时钟偏差超过 1500 ms 会断开；断开时清除扫描。

~~~json
{"schema_version":1,"type":"scan_lite","ts_ms":1795000000130,"frame_id":"map","points":[[0.35,0.72],[0.36,0.73]]}
~~~

## 当前框架边界

- 只有 Wi-Fi / 有线网络上的只读上报连接。没有独立 HTTP REST、文件上传、参数读写、任务下发、实车急停、确认应答或历史回放 API。不要把规划中的功能当成已可调用的端点。
- Pi 网关及 ROS 订阅由车端实现；地面站不解析 rosbridge 封装。地面站上的模拟状态和模拟急停不控制实车。
- 示例时间戳仅用于说明结构；实际发送时使用当前采样／事件时间。
