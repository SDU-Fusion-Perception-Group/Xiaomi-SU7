# 传感器串口协议与实机验收

范围：Jetson Orin Nano 上 HWT905 与 RPLIDAR S1 的工程对接，覆盖本次实测协议及常用控制接口。未实测的厂商扩展命令不算验收通过。测试日期：2026-11-24。

## 1. 接线与串口

| 设备 | 转接器与 Linux 驱动 | 实测节点 | 串口参数 |
|---|---|---|---|
| HWT905 | CH340（1a86:7523），ch341 | /dev/ttyUSB0 | 230400、8N1，无硬件流控；115200 已验证 |
| RPLIDAR S1 | WCH-Link（1a86:8010），cdc_acm | /dev/ttyACM0 | 256000、8N1，无硬件流控 |

节点编号可能随插拔变化，部署时按 USB 身份及物理路径核对。CH340 的 ch341 模块基于 NVIDIA L4T R39.2 官方源码为 6.8.12-1021-tegra 构建；内核变更后需重新核对模块。未做双设备同时在线验收。

## 2. HWT905：WIT 标准 UART

### 数据帧（设备 → Jetson）

固定 11 字节：

    55 TYPE D0 D1 D2 D3 D4 D5 D6 D7 SUM

SUM 为前 10 字节之和的低 8 位。16 位数据按低字节在前组装，测量原值按有符号 int16 解码。串口 read 不保证对齐；缓存不足 11 字节时等待，校验失败滑动一字节重新同步。四类帧独立到达，不把一次 read 当成同一采样时刻。

| TYPE | 数据 | 换算 |
|---|---|---|
| 51 | Ax、Ay、Az | raw × 16 × 9.80665 / 32768，m/s² |
| 52 | Wx、Wy、Wz | raw × 2000 × π / (180 × 32768)，rad/s |
| 53 | Roll、Pitch、Yaw | raw × π / 32768，rad |
| 59 | Q0、Q1、Q2、Q3 | raw / 32768，无量纲 |
| 5F | 4 个连续寄存器的返回值 | 每个 16 位小端，从所查询的起始地址依次排列 |

0x51/52/53 的前 6 个数据字节为三轴；末两字节不属于三轴，业务不得当作第四轴。坐标方向须按安装姿态做实机标定验证；不要修改厂家校准基准。

### 指令（Jetson → 设备）

固定 5 字节：FF AA REG VALUE_L VALUE_H。发送查询后，在连续测量流里按类型和校验筛出 5F。回包不携带起始地址，同一串口不要并发发起多个查询。写配置前解锁，写完用查询和实际出帧双重确认。

| 操作 | 十六进制 TX | 实测说明 |
|---|---|---|
| 读 RSW、RRATE、BAUD、AXOFFSET | FF AA 27 02 00 | 读四个连续寄存器，约 9.04 ms 回包 |
| 读 RRATE 起始的四个寄存器 | FF AA 27 03 00 | 读回的首个寄存器是 RRATE |
| 解锁 | FF AA 69 88 B5 | 在写配置或保存前使用 |
| 设 50 Hz / 100 Hz | FF AA 03 08 00 / FF AA 03 09 00 | 实测 99.89 → 50.47 → 100.43 Hz |
| 关四元数 / 恢复 | FF AA 02 0E 00 / FF AA 02 0E 02 | 0x000E 保留三类，0x020E 再开启四元数；四元数帧 151 → 0 → 150 |
| 切 115200 / 230400 | FF AA 04 06 00 / FF AA 04 07 00 | 切换后主机同步改速，再在新速率发查询 |
| 保存 | FF AA 00 00 00 | 在当前新波特率发送；两种速率均经重插复验 |

实测回包：230400 为 55 5F 0E 02 09 00 07 00 00 00 D4；115200 为 55 5F 0E 02 09 00 06 00 00 00 D3。最终为 230400、100 Hz、RSW=0x020E；复验 1 秒共 402 帧测量数据，另 1 帧寄存器回复。厂商校准、清零和恢复出厂操作不纳入本工程测试。

## 3. RPLIDAR S1：Slamtec UART

### 命令与应答

无负载命令为 A5 CMD。带负载命令按 SDK 协议组织为 A5 CMD LEN PAYLOAD XOR，校验为此前字节逐字节异或。响应描述符为 A5 5A + 4 字节小端长度/模式 + 1 字节类型；低 30 位是长度，高 2 位是发送模式。持续流的长度不是整次扫描的总字节数。

| 命令 | TX / SDK 接口 | 返回及验证 |
|---|---|---|
| 设备信息 | A5 50 | 类型 04，20 字节负载：型号、固件版本 uint16 LE、硬件版本、16 字节序列号；实测总计 27 字节，约 4 ms |
| 健康状态 | A5 52 | 类型 06，3 字节负载：状态 uint8、错误码 uint16 LE；实测总计 10 字节，约 3 ms，状态与错误码均为 0 |
| 标准扫描 | A5 20 | 描述符 A5 5A 05 00 00 40 81；随后连续 5 字节测量节点 |
| 停止扫描 | A5 25 / stop() | 实测残留 152 字节后，700 ms 无新数据；不是物理停转证明 |
| 推荐扫描 | startScan(false,true,...) | SDK 选中 DenseBoost；用 grabScanDataHq 解码逐圈结果 |
| RPM 调节 | setMotorSpeed(rpm)，RPM 模式命令 0xA8 | 该机报告支持 RPM；480 RPM 实测约 8.036 Hz，33 个间隔；按项目确认不使用低于 480 RPM 的运行档 |
| 停机 | stop() 后 setMotorSpeed(0) | 两个 SDK 调用均成功；未独立确认电机物理停转 |

SDK 还定义强制扫描 (21)、复位 (40)、采样率查询 (59)、Express/HQ (82/83)、配置读取/设置 (84/85) 和 PWM (F0)。这些具体命令未逐条做实机验收，不把其他型号支持情况等同于本机。DenseBoost 不按标准 5 字节节点解包。

### 标准扫描节点与 SDK 输出

- 标准节点：第 0 字节 bit0 为新圈标记，bit1 为其反码，bit7:2 为质量；第 1–2 字节小端，bit0 为检查位（应为 1），右移 1 后除以 64 得角度（度）；第 3–4 字节小端除以 4 得距离（mm）。距离为 0 表示无有效距离，不计入最近障碍物。
- 标准扫描实测：3 秒收到 10,375 字节，2,073 个结构有效节点，1,925 个距离非零；启动窗口只有 4 个新圈标记，不用它估计稳态转速。
- SDK HQ 节点：角度 deg = angle_z_q14 × 90 / 16384；距离 m = dist_mm_q2 / 4000。按完整圈的相邻时间间隔计算频率，不能用串口吞吐率代替转速。360 RPM 指令虽返回成功但没有达到目标，不是有效工作档。
- 工程的三向扇区基于雷达原始角度：前 0°±15°、左 270°±15°、右 90°±15°。安装后用实物验证零位、左右与车体坐标是否一致；无有效距离时不要用 0 代替。
