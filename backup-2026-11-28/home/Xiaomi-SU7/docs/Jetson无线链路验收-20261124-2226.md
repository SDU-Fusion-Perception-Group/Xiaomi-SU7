# Jetson 5 GHz 热点排障与验收记录｜2026-11-24

环境：Jetson Orin Nano，Ubuntu 24.04，6.8.12-1021-tegra，RTL8822CE；Windows Intel AX101。Jetson-Lab-5G 使用信道 36、20 MHz。管理走有线 SSH，业务探测绑定 WLAN。

## 故障与处理
21:17:29、21:31:56 均记录到 SMMU 地址异常、PCIe MalfTLP 和 rtl88x2ce 恢复失败。只关闭接口省电未解决；热点重新激活时接口省电曾弹回 on。重载现有模块后，曾遇到 supplicant 报 Driver does not support AP mode；重启无线认证服务后恢复 AP-ENABLED。

NetworkManager 全局 wifi.powersave 从 3 改为 2，临时热点配置显式设为 2。驱动 rtw_power_mgnt 从 2 改为 0，rtw_ips_mode 从 1 改为 0；无线 PCIe ASPM 原本已关闭。Jetson 持久覆盖文件：/etc/NetworkManager/conf.d/zz-robot-wifi-powersave-off.conf 和 /etc/modprobe.d/zz-robot-rtl8822ce-power.conf。有效配置已回读，未更换驱动，未重启整机。

## 验收结果

两端均未收到重复包。测试窗口无新增对应 SMMU/PCIe 错误，无 AP 关闭或客户端断开事件。结束时仍关联，接口回读 `Power save: off`。零丢包不意味着所有包均在控制时限内到达。

结论：组合配置通过本次静态负载长测，未证明某单一参数是底层故障的唯一根因。热点配置仍为临时；冷启动恢复、移动场地和真实控车负载未验收。此文件是验收摘要，非原始日志。复测脚本：工作区根目录 wifi_duplex_soak.py。
