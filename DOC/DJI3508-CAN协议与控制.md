# DJI 3508 / C620 CAN 控制协议

本文对应 CAN1 上的 DJI 3508 无刷电机和 C620 电调。协议依据 RoboMaster 电调公开 CAN 协议整理：[RoboMaster 电调协议](https://bbs.robomaster.com/wiki/20204847/817324?source=7)。

## 1. 硬件与速率

| 项目 | 值 |
| --- | --- |
| 控制器接口 | STM32H723 FDCAN1 |
| 引脚 | PD0 RX、PD1 TX |
| 帧格式 | Classic CAN 2.0，标准帧，8 字节 |
| 波特率 | 1 Mbps，FDCAN 内核时钟实测 80 MHz |
| 控制 ID | `0x200`，8 字节同时包含电调 ID 1–4 |
| 当前电调 | ID 2，反馈帧 `0x202` |

当前工程控制电调 ID 2，即 `0x200` 的第 2、3 字节，反馈 ID 为 `0x202`。

## 2. 控制帧

`0x200` 的 8 字节依次为四台电机的电流命令，均为大端有符号 16 位：

| 字节 | 电机 | 含义 |
| --- | --- | --- |
| 0–1 | ID 1 | 电流命令，`-16384..16384` |
| 2–3 | ID 2 | 电流命令 |
| 4–5 | ID 3 | 电流命令 |
| 6–7 | ID 4 | 电流命令 |

`16384` 对应 C620 最大输出电流。正负号决定方向。命令必须周期发送，当前工程为 100 Hz；超过 100 ms 未收到反馈则标记离线。

## 3. 反馈帧

`0x201`–`0x204` 的数据格式：

| 字节 | 类型 | 含义 |
| --- | --- | --- |
| 0–1 | uint16 | 转子机械角度，`0..8191`，对应 `0..360°` |
| 2–3 | int16 | 转子转速，rpm |
| 4–5 | int16 | 实际电流原始值 |
| 6 | uint8 | 电调温度，℃ |
| 7 | uint8 | 保留 |

3508 减速比按 19:1 使用。输出轴转速为 `转子 rpm / 19`，输出轴一圈对应转子角度累加 `8192 × 19`。

## 4. 工程命令

USB 命令：

```text
m3508 1000
m3508 -1000
stop
```

第一条使 ID 2 正转，第二条反转，`stop` 将电流命令清零。CLI 返回 `3508 online angle rpm current temp`，其中 `online=1` 表示已收到 `0x202`。

## 5. 底层诊断结论

当前固件已修复以下问题：

1. FDCAN1 标称时序恢复为官方 1 Mbps 配置：FDCAN 内核时钟 120 MHz，预分频 24，`TSEG1=2`，`TSEG2=2`。
2. DJI 驱动固定使用 FDCAN1，PD0 为 RX、PD1 为 TX；FDCAN3 不再与 DJI 句柄混用。
3. CAN1 接收统一由公共 FIFO0 回调分发到 DJI 解析器，反馈帧必须是标准数据帧、8 字节、ID `0x201..0x204`。
4. `m3508` CLI 现在输出 `tx/rx/txerr`，可区分“未发送”“发送无 ACK”和“已收到反馈”。

最近一次实测：`tx=47 rx=0 txerr=1`。这证明控制帧已经从 MCU 发送，当前仍未收到 C620 的反馈帧。若 `txerr` 增加且 `rx` 保持 0，优先检查 C620 电源、CAN 收发器连接、终端电阻和电调是否确实启用 CAN 回传。

## 6. 与步进驱动的关系

LYX 步进驱动仍使用 USART3 RS485，负责精确距离和角度执行。DJI 3508 使用 CAN1，负责底盘驱动电流控制。两者的命令都从同一个 USB 命令行进入，但物理总线、帧格式和单位互不复用。
